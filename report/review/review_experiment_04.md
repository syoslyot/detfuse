## 總評

本份報告的優點在於忠實記錄了兩次獨立執行的差異，並對 FP 做出有建設性的質疑（標注錯誤假說）。但整體而言，許多觀察停留在「記錄現象」的層次，尚未形成可驗證的解釋。以下依四個維度展開。

---

## 1. 可重現性與實驗設計（Reproducibility & Setup）

**提問**

- 報告提到結果差異來自「batch shuffle、weight init」，但 random seed 並未固定或記錄。這意味著 experiment_03 和 experiment_04 的任何差異，都無法區分是「訓練隨機性」還是「環境差異（Colab session、CUDA 版本、記憶體狀態）」。請問你如何確認兩次執行的唯一變因只有隨機性？

- 訓練 loss 在三個 epoch 都系統性高於 experiment_03（0.1433 vs 0.1363、0.0561 vs 0.0470、0.0228 vs 0.0163），這樣的一致性偏高不像純粹的隨機波動，更像是初始化或資料順序上的結構性差異。報告沒有提到這個現象，是否考慮過？

- 測試集正例數量：報告提到「58/58 正例全部命中」，但 CLAUDE.md 記錄 `test_data.json` 有 67 個正例。請問評估用的測試集與原始標記資料之間有無過濾或子集抽樣？若有，篩選條件是什麼？這對結論的適用範圍有直接影響。

**建議**

固定並記錄所有隨機源的 seed（`torch.manual_seed`、`numpy.random.seed`、`transformers.set_seed`、Colab 環境的 Python `random.seed`），是讓實驗可重現的最低門檻，也是讓「多 seed 實驗」有意義的前提。

---

## 2. 評估方法（Evaluation Methodology）

**提問**

- 測試集的正負例比為 58:176（約 1:3），但報告的「下一步」中也提到需要「建立真實分佈測試集（正負比 1:30+）」。這意味著你已經意識到目前的測試集與真實部署情境相差一個數量級。那麼，目前 Precision 85.29%、F1 92.06% 這些數字在實際系統上的意義是什麼？如果真實分佈是 1:30，FP 數量對使用者體驗的衝擊會是現在的幾倍？

- Precision / Recall / F1 的選擇是合理的，但這個任務的 FP 代價和 FN 代價是否對等？如果系統漏掉一筆真正的免費食物（FN），和多推一筆無關貼文（FP），對使用者的影響哪個更嚴重？這個判斷應該反映在你最終選擇的部署閾值上，而不只是報告一個固定的 τ=0.50。

- 報告中 Fusion ft 和 fine-tuned L2 的數字完全相同，代表 L1 的貢獻為零。但你有沒有計算在 L1 有貢獻（α 較大）時，Fusion 的 Precision-Recall curve 如何變化？光是說「Fusion 無效」而不附上 curve 或不同 α 的掃描結果，結論的說服力有限。

**建議**

考慮以 AUC-ROC 或 Precision-Recall AUC 作為補充指標，特別是在正負比差距大的情境下，單一閾值下的 F1 容易遮蔽模型在其他操作點的行為。

## 3. 結論的有效性（Validity of Claims）

**提問**

- **「FP 是標注錯誤而非模型錯誤」**：這個假說有吸引力，但目前只是推測。「電機營多的便當」確實可能是真正的免費食物，但也可能因為發文脈絡（不向外開放、限定對象）而應標為負例。請問你有沒有一個明確的標注準則（annotation guideline），定義什麼樣的免費食物屬於正例？若沒有，這個假說的驗證標準是什麼？

- **「Recall 100% 是模型偏 lenient」**：這是一個描述，但背後的機制是什麼？是模型學到了過於寬鬆的特徵，還是訓練集中有足夠的多樣性讓模型真正泛化？這兩種解釋對下一步的處置完全不同——前者需要調整閾值或加入 hard negative，後者則可以接受。

- **「F1 相近代表整體品質相當」**：F1 是一個聚合指標。experiment_03（F1 92.98%）和 experiment_04（F1 92.06%）看起來接近，但 FP 從 3 變成 10、FN 從 5 變成 0，這是截然不同的錯誤分佈。對一個實際系統來說，這兩種模型的行為差異是顯著的，「整體品質相當」的說法需要更謹慎。

**做得好的地方**

主動指出 FP 模式並提出標注錯誤假說，這是好的錯誤分析思路，遠比只報告數字然後說「模型還需改善」有價值。

## 4. 下一步（Next Steps）

**現有下一步的評估**

| 項目 | 評估 |
|------|------|
| 人工複查 FP | 最優先，且應同時建立正式的標注準則，否則複查結果無法複用 |
| 多 seed 實驗 | 必要，但建議先固定 seed 格式再做，否則實驗仍不可重現 |
| 調整 α | 合理，但應做系統性掃描（如 α ∈ {0.1, 0.2, …, 0.9}）並畫出 F1 曲線，而非只試幾個點 |
| 真實分佈測試集 | 最重要的長期投資，但實作上需要思考如何取得足夠的真實負例 |

**報告未提到的方向**

1. **Calibration 分析**：fine-tuned L2 的 softmax 輸出（或 logit）是否良好校準？如果模型對所有樣本都輸出極端的 0 或 1，那 τ=0.50 的設定其實沒有調整空間，這也可能解釋為什麼 Fusion 的 α 調整沒有效果。

2. **Hard negative mining**：訓練集的負例是否包含與正例高度相似的困難樣本（如「活動報名才能領便當」、「限社員」）？若訓練集的負例太容易，模型在部署時遇到邊界案例會更容易出錯。

3. **Error consistency 分析**：experiment_03 和 experiment_04 各自的 FP/FN，有多少是重疊的？若兩次都錯在同一批樣本，表示這些是模型系統性的盲點（值得針對性加強）；若錯誤完全不重疊，則說明隨機性影響大，需要更多次實驗才能得出穩定結論。

## 總結建議

本份報告在記錄實驗結果上是合格的，但距離「可信的研究結論」還有幾個缺口：**seed 未固定**（可重現性問題）、**測試集與真實分佈差距懸殊**（外部效度問題）、**Fusion 分析不完整**（結論過早）。建議在下次實驗前，先把標注準則和 seed 管理這兩件基礎工作確立，讓後續每次實驗的結果都能累積成可比較的證據，而不是各自獨立的快照。
